Switching to one of EDIS's current **"Kaffee" hosting products** is more than a simple account upgrade — it is a full platform migration. The new and old hosting environments run on separate systems, so all website files, databases, email accounts, and configurations must be moved manually before the domain is switched over. Taking a methodical approach ensures your site stays online throughout the process and that nothing is missed.

<Warning>
  Do not cancel or disable your existing hosting package until you have fully tested the new environment and confirmed that everything — website, email, and SSL — is working correctly.
</Warning>

## Migration Overview

<Steps>
  <Step title="Order the New Hosting Package">
    Log in to the customer portal at [manage.edis.at/client/](https://manage.edis.at/client/) and order the **"Kaffee" hosting product** that suits your needs. Review the file-count and storage limits of the new package before ordering — every product has its own technical limits, and these may differ from your current plan.

    <Tip>
      If you are unsure which package is right for your workload, contact EDIS support at [hosting@edis.at](mailto:hosting@edis.at) or call **+43 1 909 4111** (Monday–Friday, 08:00–17:00).
    </Tip>
  </Step>
  <Step title="Wait for Provisioning Confirmation">
    You will receive a confirmation message once the new hosting package is active. If you do not receive it within the expected timeframe, check the order status in the customer portal before placing a second order. Contact support if the package is not provisioned after a reasonable wait.
  </Step>
  <Step title="Back Up Everything on the Old Hosting Package">
    Before touching anything on the new server, create complete backups of:

    - **All website files** — download everything from your document root via FTPS or SFTP.
    - **All databases** — export each database as a `.sql` file using phpMyAdmin (available in the vHost area) or via SSH with `mysqldump`.
    - **Email** — if you use EDIS email hosting, back up all mailbox contents. A simple way to do this is to connect with an IMAP client and copy all folders to a local profile or another mail account.

    <Warning>
      Check your mailbox storage carefully before migrating. Each product has both a total storage budget and a per-mailbox limit. Delete unwanted emails (including trash and spam folders) on the old account before the move, and verify that the new package can accommodate your data.
    </Warning>
  </Step>
  <Step title="Set Up the Document Root on the New Package">
    Log in to the vHost area of the **new** hosting package at [manage.edis.at/vhost/](https://manage.edis.at/vhost/). Under **Apache → SubDomains**, configure the document root path for your domain. Use a temporary subdomain or the default hostname to test the site before the DNS switch.
  </Step>
  <Step title="Upload Website Files to the New Package">
    Connect to the new hosting package via FTPS or SFTP and upload your website files to the document root you configured. Confirm you are connecting to the **new** server and not the old one — check the hostname in your FTP client settings.
  </Step>
  <Step title="Create the Database on the New Package">
    In the vHost area of the new package, go to **Database → Expert Mode** and create a new database user and database. Then import your `.sql` backup:

    - Use **phpMyAdmin** in the vHost area, or
    - Connect via SSH and run: `mysql -u newuser -p newdatabase < backup.sql`

    After the import, update your application's database configuration file with the new credentials:
    - **WordPress:** edit `wp-config.php` — update `DB_NAME`, `DB_USER`, `DB_PASSWORD`, and `DB_HOST`.
    - **Joomla:** edit `configuration.php` — update the corresponding database fields.
    - **Other CMSs:** refer to their documentation for the correct configuration file.
  </Step>
  <Step title="Check Configuration Files for Old Paths">
    Some configuration files — such as `.user.ini` — may contain absolute file paths that reference directories on the old hosting package. Search for and update any such paths.

    <Note>
      Only change values that actually contain old path references. Do not delete entire configuration files or settings entries on the assumption they are no longer needed — this can break your application.
    </Note>
  </Step>
  <Step title="Verify the PHP Version">
    In the vHost area of the new package, go to **Apache → PHP Version** and check which PHP version is selected. Compare this with the PHP version your application was running on previously. If there is a mismatch, adjust the PHP version before testing.

    <Warning>
      Running a CMS on an incompatible PHP version will cause errors or a blank page. Always match the PHP version to your application's requirements before going live.
    </Warning>
  </Step>
  <Step title="Test on the New Package Before Switching DNS">
    Use the temporary hostname or a modified local `hosts` file to browse your website on the new package and verify:

    - All pages load correctly.
    - Forms, logins, and e-commerce functions work.
    - Images and file uploads are in place.
    - HTTPS is active and the SSL certificate is valid.

    Fix any issues before proceeding to the DNS switch.
  </Step>
  <Step title="Migrate Email Accounts">
    Re-create all mailboxes, forwarders, and routing rules on the new package in the vHost area under **Email**. Then move mailbox contents from the old to the new account using an IMAP client — connect both accounts simultaneously and drag-and-drop folders between them.

    Test sending and receiving on the new mailboxes before cutting over.
  </Step>
  <Step title="Switch the Domain to the New Package">
    Once you are confident everything works on the new package, contact EDIS to reassign the domain:

    - **Email:** [hosting@edis.at](mailto:hosting@edis.at) — include your customer number, domain name(s), and the new hosting package ID.
    - **Phone:** +43 1 909 4111 (Monday–Friday, 08:00–17:00)
    - **WhatsApp:** +43 670 3084988

    EDIS will link the domain to your new hosting package. After the switch, verify that the domain resolves correctly and that HTTPS continues to work.

    <Note>
      If your DNS is managed externally (outside EDIS), you must also update the A and AAAA records at your DNS provider to point to the IP address of the new hosting package.
    </Note>
  </Step>
  <Step title="Monitor and Cancel the Old Package When Ready">
    Keep the old hosting package active for a few days after the migration as a safety net. Once you are fully satisfied with the new setup, you can cancel the old package through the customer portal.

    If your old plan has already been renewed or prepaid, contact [hosting@edis.at](mailto:hosting@edis.at) to discuss any applicable credit or proration.
  </Step>
</Steps>

## Migration Checklist Summary

Use this checklist to track your progress:

<AccordionGroup>
  <Accordion title="Pre-migration">
    - [ ] New hosting package ordered and provisioned
    - [ ] All website files backed up locally
    - [ ] All databases exported as `.sql` files
    - [ ] Mailbox contents backed up
    - [ ] PHP version on old package noted
    - [ ] File count and storage usage compared with new package limits
  </Accordion>
  <Accordion title="New Package Setup">
    - [ ] Document root configured in Apache → SubDomains
    - [ ] Website files uploaded to new package
    - [ ] Database created and `.sql` imported
    - [ ] Application config files updated with new DB credentials
    - [ ] Old absolute paths removed from `.user.ini` and other config files
    - [ ] PHP version set to match old package
  </Accordion>
  <Accordion title="Testing">
    - [ ] Site loads correctly via temporary hostname
    - [ ] Admin login works
    - [ ] Forms and dynamic functions tested
    - [ ] HTTPS active with valid SSL certificate
    - [ ] Email accounts re-created and tested
  </Accordion>
  <Accordion title="Go-Live">
    - [ ] EDIS contacted to reassign domain to new package
    - [ ] External DNS records updated (if applicable)
    - [ ] Live domain tested over HTTP and HTTPS
    - [ ] Old hosting package scheduled for cancellation
  </Accordion>
</AccordionGroup>
