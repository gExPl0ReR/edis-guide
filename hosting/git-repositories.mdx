Git is available on EDIS web hosting servers and can be used to clone remote repositories directly into your hosting account. You connect to your hosting account via SSH, then Git establishes its own outbound connection to the repository provider using the HTTPS protocol. Git transport over SSH is not supported in the EDIS hosting environment — always use the HTTPS clone URL provided by your repository host.

## Cloning a Repository

<Steps>
  <Step title="Verify SSH access for your hosting product">
    Not all EDIS hosting packages include SSH access. Log in to the [vHost management panel](https://manage.edis.at/vhost/) and confirm that SSH is enabled for your account before proceeding.
  </Step>
  <Step title="Connect to your hosting account via SSH">
    Open a terminal and log in using the SSH credentials for your vHost.
  </Step>
  <Step title="Navigate to the target directory">
    Change into the directory where you want to place the cloned repository:
    ```bash
    cd /home/yourVhostID/html
    ```
    Replace `yourVhostID` with your actual hosting identifier.
  </Step>
  <Step title="Clone the repository over HTTPS">
    Use the HTTPS clone URL from your repository provider. For example, to clone from GitLab:
    ```bash
    git clone https://gitlab.com/ORGANISATION/PROJECT.git
    ```
    Replace `ORGANISATION` and `PROJECT` with the actual values for your repository. For GitHub:
    ```bash
    git clone https://github.com/ORGANISATION/PROJECT.git
    ```
  </Step>
</Steps>

<Note>
  A successful SSH login to your hosting account does not automatically grant access to your remote repository. Repository access depends on your permissions with the repository provider (GitLab, GitHub, Bitbucket, etc.), which is separate from your EDIS hosting credentials.
</Note>

## Private Repositories and Authentication

When cloning a private repository, your repository provider will require authentication. Use the method your provider supports — typically a personal access token (PAT) passed as part of the URL or entered at the prompt:

```bash
git clone https://oauth2:YOUR_ACCESS_TOKEN@gitlab.com/ORGANISATION/PROJECT.git
```

<Warning>
  Never include tokens, passwords, or other credentials in support requests, ticket messages, or public examples. If credentials have already been exposed, revoke and replace them immediately through your repository provider's security settings.
</Warning>

Also ensure that your cloned project files are not inadvertently accessible over the web. Place repositories outside your public web root, or protect the directory with an `.htaccess` rule if they must reside within it.

## Troubleshooting Clone Errors

If a `git clone` command fails, work through these checks before contacting support:

- **Protocol**: Confirm you are using an `https://` URL, not an `ssh://` or `git@` address.
- **Repository URL**: Copy the HTTPS clone URL directly from the repository provider's interface to avoid typos.
- **Permissions**: Verify that your account has read access to the repository on the provider's side.
- **Authentication**: For private repositories, check that your token is valid and has not expired.
- **Transport module**: If Git reports a missing transport module, check the exact Git command you ran and the environment in which it executed.

When contacting EDIS support, provide the affected vHost identifier, the execution context (e.g., SSH session), and the full error message with any tokens or passwords removed.
