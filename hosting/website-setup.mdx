Every domain or subdomain on your EDIS hosting package can be pointed to its own directory on the server — known as the **document root**. This allows you to run completely independent websites, for example a separate WordPress installation on a subdomain, without them interfering with each other. You configure document roots inside the vHost management area under the Apache settings.

## Assign a Document Root

<Steps>
  <Step title="Log In to the vHost Area">
    Go to [manage.edis.at/vhost/](https://manage.edis.at/vhost/) and sign in. If you have not yet set up direct vHost access, log in via the customer portal at [manage.edis.at/client/](https://manage.edis.at/client/) and click the green arrow next to your hosting package.
  </Step>
  <Step title="Open Apache Settings">
    In the vHost navigation menu, click **Apache**.
  </Step>
  <Step title="Select SubDomains">
    Under the Apache section, click **SubDomains**. This is where you manage document root assignments for all domains and subdomains linked to your hosting package.
  </Step>
  <Step title="Choose the Domain or Subdomain">
    Locate the domain or subdomain you want to configure and select it. You can assign a custom document root to any entry in this list.
  </Step>
  <Step title="Create the Target Directory via FTP">
    Before entering a path, create the target directory on your hosting account using an FTP client. Use a path such as:

    ```text
    /home/userid/www/home/my-new-site/
    ```

    Replace `userid` with your actual hosting username and `my-new-site` with the folder name of your choice. Use FTPS or SFTP for a secure connection.
  </Step>
  <Step title="Enter the Document Root Path">
    Back in the SubDomains settings, point the domain or subdomain to the directory you just created. Enter the full server path, for example:

    ```text
    /home/userid/www/home/my-new-site/
    ```
  </Step>
  <Step title="Save Your Changes">
    Click **Save** (or the equivalent button) to activate the new document root for that domain or subdomain.
  </Step>
</Steps>

<Note>
  Activating a new domain or subdomain assignment can take up to **10 minutes** to propagate. During this time the old document root may still be served. Wait a few minutes before uploading files or testing the URL.
</Note>

After saving, upload your website files into the directory you specified. Any CMS or application placed in that folder will be served when visitors access that domain or subdomain.

## Connecting an Additional Domain to Your Hosting

Registering or transferring a domain to EDIS does not automatically attach it to a hosting package. After the domain is available in your account, you must:

1. Ensure the domain's DNS A record (and AAAA record for IPv6) points to your hosting package's IP address.
2. Assign a document root to the domain in the SubDomains section as described above.
3. Verify that SSL/HTTPS is working correctly for the new domain.

<Tip>
  If you are unsure which IP address to use for the DNS records, log in to the vHost area and check the hosting package details, or contact [hosting@edis.at](mailto:hosting@edis.at).
</Tip>

## Multiple Domains Sharing the Same Directory

By default, the primary domain of a hosting package points to the root web directory. If you assign an additional domain to the same physical folder, **both addresses will serve identical content**. This is not always desirable.

To avoid duplicate-content issues:

- Decide which URL should be the canonical (primary) address.
- Set up a redirect in `.htaccess` so all traffic for the secondary domain is forwarded to the primary one.
- Add a `canonical` meta tag in your HTML to signal the preferred URL to search engines.

<Warning>
  Do not copy `.htaccess` redirect rules from external sources without reviewing them first. Incorrect rules can cause redirect loops or make your site inaccessible. Always test both HTTP and HTTPS access after making changes.
</Warning>

## Temporarily Taking a Website Offline for Maintenance

If you need to display a maintenance page instead of your normal site, you have two main options:

- **CMS maintenance mode** — most content management systems (WordPress, Joomla, etc.) include a built-in maintenance mode that shows a custom page to visitors while keeping the admin dashboard accessible.
- **Alternative document root** — point the domain to a different directory containing only a static maintenance page. Remember to restore the original document root when maintenance is complete.

<Note>
  Switching to a maintenance document root does not automatically block access via other subdomains or direct file paths. Test all relevant URLs after making the change.
</Note>
