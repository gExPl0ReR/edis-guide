EDIS web hosting plans enforce two distinct types of resource limits: a **storage space limit** (how much data you can store, measured in GB) and a **file count limit** (how many filesystem objects you can have, measured in inodes). These are independent constraints — you can exhaust one while the other still has capacity. Free disk space does not mean you can create more files, and vice versa.

<Info>
  Storage space, file count, and mailbox quotas are separate limits. Always identify which specific resource a warning refers to before taking action. Check the limit figures for your specific hosting product, as values differ between plans and product generations.
</Info>

## Understanding the Two Limits

<CardGroup cols={2}>
  <Card title="Storage Space Limit" icon="hard-drive">
    Caps the total volume of data you can store, expressed in gigabytes. Large files — such as backups, videos, or database dumps — consume this quota quickly.
  </Card>
  <Card title="File Count (Inode) Limit" icon="file">
    Caps the total number of filesystem objects: files, directories, and symlinks each count as one inode. Applications that create many small files (caches, session files, log entries, emails) can hit this limit even when plenty of disk space remains.
  </Card>
</CardGroup>

When either limit is reached, the server will refuse to create new files or store additional data. Depending on the application, this may appear as a generic write error, a failed upload, or a broken installation process.

## What Happens When You Reach a Limit

| Situation | Likely Cause |
|-----------|-------------|
| Upload fails despite free disk space shown | File count (inode) limit reached |
| New files cannot be created anywhere | Inode limit or storage limit reached |
| Application installation halts unexpectedly | Inode limit reached (many small files created during install) |
| Email delivery fails to a mailbox | Mailbox quota reached (separate from web storage) |

## Checking Your Usage

Log in to the [vHost management panel](https://manage.edis.at/vhost/) to view the current storage and file count statistics for your hosting account. Keep in mind that the statistics display is updated on a scheduled basis — typically once per day. If you have recently deleted files, the displayed figures may not yet reflect those changes.

<Note>
  If your usage appears to be below the limit in the current display but you recently received a warning, the two readings may refer to different points in time. Note the timestamp of the warning, the measured values, and your product's limit before contacting support.
</Note>

## Cleaning Up to Free Resources

Before deleting anything, create a backup of your current state. Then identify which category of files is consuming the most resources:

<Steps>
  <Step title="Find large files consuming storage space">
    Connect via SSH or SFTP and look for large files that are no longer needed: old database dumps, archived backups stored within your web space, unused media uploads, and large log files.
  </Step>
  <Step title="Find directories with many small files consuming inodes">
    Common sources of high inode usage include application caches (e.g., `/cache/`, `/tmp/`), PHP session file directories, old log directories with many rotated files, and email storage. Use SSH to check inode counts per directory:
    ```bash
    find /home/yourVhostID/ -maxdepth 2 -type d | while read dir; do
      count=$(find "$dir" | wc -l)
      echo "$count $dir"
    done | sort -rn | head -20
    ```
  </Step>
  <Step title="Delete only what is safe to remove">
    Confirm that any directory or file you plan to delete does not belong to an active application. Do not delete emails if the warning relates to web filesystem usage — mailbox and web storage are accounted for separately.
  </Step>
  <Step title="Monitor the updated statistics">
    Wait for the next statistics update cycle (typically the following day) and verify that your usage has dropped below the limit.
  </Step>
</Steps>

<Warning>
  Do not randomly consolidate application files or delete email data when the issue is web disk usage. Investigate the actual source of the excessive file count before taking action, and always keep a backup before deleting anything.
</Warning>

## S3 Object Storage and Shared Budgets

On hosting products where web space and S3 object storage share a common budget, any S3 capacity you reserve is drawn from that shared pool — it does not add to your web space. Check your product's allocation rules before reserving S3 capacity.

In most configurations, S3 objects are **not** counted against the web filesystem's inode limit. The S3 usage, reserved S3 capacity, and web file count must therefore be reviewed separately. This also means S3 storage is not unlimited — it is bounded by whatever is allocated to it from your overall product budget.

## Mailbox Quotas and Plan Changes

Mailbox storage is typically governed by its own quota, separate from web storage. If you have multiple mailboxes, check both the per-mailbox limits and the aggregate limit for your plan. Cancelling a mailbox migration or performing a technical cleanup does not automatically end any separately billed additional quota service.

If your application is permanently growing beyond what your current plan provides, compare the actual capacity and terms of a higher-tier plan. Agree on the scope and timing of any upgrade explicitly with EDIS. For details on mailbox limits and additional mailbox costs, see the [mailbox setup guide](/email/mailbox-setup).
