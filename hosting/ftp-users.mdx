FTP (File Transfer Protocol) lets you transfer files between your computer and your webhost. The EDIS vHost panel gives you full control over your FTP users — you can create them, restrict how long they remain valid, and deactivate them when they are no longer needed.

## Creating an FTP User

<Steps>
  <Step title="Open the vHost management panel">
    Go to [manage.edis.at/vhost/](https://manage.edis.at/vhost/) and log in with your hosting credentials.
  </Step>
  <Step title="Navigate to FTP Management">
    In the left-hand menu, click **FTP**, then select **Management**.
  </Step>
  <Step title="Create a new FTP user">
    Click **FTP User erstellen** (Create FTP User). A form will appear where you can enter the new user's details, including the username, password, and home directory.
  </Step>
  <Step title="Save the new user">
    Fill in all required fields and confirm. The new FTP user is now active and ready to use.
  </Step>
</Steps>

<Note>
  Use a long, unique password that meets the requirements shown on the form. The message "Password must be in the ASCII charset" does not exclude all special characters — it refers to the allowed character set. Check the current requirements displayed for that specific account.
</Note>

## Setting a Time Limit for an FTP User

You can restrict the validity period of any FTP user so that access is automatically suspended after a set date. This is particularly useful when granting temporary access — for example, to a developer or external contractor.

Once the validity period expires, the user is **suspended**, not deleted. The account and its settings are preserved, so you can reactivate it later if needed.

To set a time limit, open the FTP user's settings in **FTP → Management** and enter an expiry date in the validity field.

<Tip>
  If you know you only need FTP access for a specific project or time window, always set an expiry date. This reduces your attack surface without requiring you to remember to delete the account manually.
</Tip>

## Deactivating an FTP User

When an FTP account is no longer needed, deactivate it promptly rather than leaving it active. In **FTP → Management**, open the user you want to disable and set its status to inactive.

<Warning>
  Deactivating an FTP user reduces your attack surface, but it does not guarantee that access via other accounts, applications, or already-compromised credentials is also blocked. If you are responding to a security incident, audit all access paths — including other FTP users, SSH users, and application credentials.
</Warning>

## Troubleshooting Login Issues

After changing a password, watch for the success message in the panel. If the new password is rejected at login, the change may not have been saved — return to the panel and verify.

If FileZilla shows "TLS connection established" followed immediately by "530 Login incorrect", the connection to the server succeeded but the login itself failed. Check:

- The username and password are correct and match the account shown in the panel.
- The FTP user is active and its validity period has not expired.
- You are connecting to the FTP hostname of the correct webhost (not a URL you would open in a browser).
- The correct protocol and port are selected in your FTP client (see [FTP Connection Settings](/hosting/ftp-settings)).

When contacting support about a login failure, provide the sanitised error output, the timestamp, the server hostname, and the protocol used. Do not include your password in any support message.

<Info>
  A successfully changed password alone does not confirm a working file upload. Test the full connection — including a directory listing and a small test transfer — before relying on the account for production use.
</Info>
