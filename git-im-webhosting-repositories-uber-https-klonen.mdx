---
title: "Git im Webhosting: Repositories über HTTPS klonen"
---

Sie melden sich per SSH an Ihrem Webhost an. Wenn Git anschließend ein externes Repository abruft, baut es eine eigene Verbindung zum Repository-Anbieter auf. Für diesen Git-Transport verwenden Sie die HTTPS-Clone-Adresse; Git-Transport über SSH ist laut EDIS-Anleitung nicht freigegeben.

<a id="g5gSL" />

## Repository über HTTPS klonen

Prüfen Sie, ob Ihr Hostingprodukt SSH unterstützt. Melden Sie sich mit den Zugangsdaten des betroffenen Webhosts an und wechseln Sie in das vorgesehene Projektverzeichnis. Verwenden Sie dann die HTTPS-Adresse Ihres Repository-Anbieters.

Allgemeines Beispiel: git clone [https://gitlab.com/ORGANISATION/PROJEKT.git](https://gitlab.com/ORGANISATION/PROJEKT.git)

Ersetzen Sie Organisation und Projekt durch die tatsächlichen Angaben Ihres Repositorys. Das Beispiel legt kein Repository an und erteilt keine Zugriffsberechtigung.

<a id="2BGI9" />

## Private Repositories und Zugangsdaten

Verwenden Sie die vom Repository-Anbieter unterstützte Authentifizierung. Schreiben Sie Tokens und Kennwörter nicht in öffentliche Beispiele oder Supportnachrichten. Achten Sie darauf, dass Zugangsdaten und Projektdateien nicht unbeabsichtigt über das Web erreichbar sind.

<a id="zGpY6" />

## Fehler gezielt unterscheiden

Prüfen Sie Protokoll, Repository-Adresse, Berechtigung und den tatsächlich ausgeführten Git-Befehl. Wenn bereits HTTPS verwendet wird, reicht die erneute Empfehlung „HTTPS verwenden“ nicht aus. Eine Meldung über ein fehlendes Transportmodul muss anhand des konkreten Git-Aufrufs und seiner Ausführungsumgebung geprüft werden.

Nennen Sie dem Support den betroffenen Webhost, den Ausführungskontext und die vollständige bereinigte Fehlermeldung. Entfernen Sie Tokens und Kennwörter. Eine erfolgreiche SSH-Anmeldung bestätigt noch keinen erfolgreichen Repository-Zugriff.
