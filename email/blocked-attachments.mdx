When an email attachment is rejected or disappears in transit, the cause can be one of several distinct filtering layers — and identifying the right one determines the correct fix. A blocked attachment does not always mean the file is dangerous; it may simply match a file type restriction or exceed a size limit. This guide explains the most common causes and describes what you can do in each case.

Before troubleshooting, gather these details: sender address, recipient address, timestamp with time zone, file name, file type (extension), and the complete error message if one was returned. Note whether the failure happened during upload, during sending, or as a bounce from the recipient's server — these are different stages and point to different causes.

<AccordionGroup>

  <Accordion title="Blocked File Type (Extension Restriction)">
    Certain file types are blocked by EDIS mail filters or by the recipient's mail server for security reasons. Commonly restricted types include executable files and scripts:

    - Windows executables: `.exe`, `.msi`, `.bat`, `.cmd`, `.com`, `.scr`
    - Script files: `.js`, `.vbs`, `.ps1`, `.wsf`
    - Macro-enabled Office files: `.xlsm`, `.docm`, `.xlam`
    - Installer packages: `.jar`, `.app` (in some configurations)

    This is not an exhaustive list — the active filter configuration may differ, and the same file type can be blocked by either the EDIS outbound filter or the recipient's inbound filter.

    **What to do:**
    - Upload the file to a cloud storage service (Google Drive, Dropbox, OneDrive, or similar) and send a sharing link instead of attaching the file directly.
    - Discuss an alternative transfer method with the recipient — for example, SFTP or a secure file transfer portal.
    - Contact [hosting@edis.at](mailto:hosting@edis.at) to have the specific file and message reviewed. Include the sender, recipient, file name, and timestamp.

    <Warning>
      Do not attempt to bypass the filter by renaming the file extension, nesting it in an archive, or using a password-protected archive. These techniques are recognised by modern filters, may cause the entire message to be rejected, and can result in your account being flagged for abuse.
    </Warning>
  </Accordion>

  <Accordion title="File Size Limit Exceeded">
    EDIS mail servers and most receiving mail servers enforce a maximum attachment size. Even if your sending client accepts the upload, the recipient's server may reject the message if the encoded attachment size exceeds its limit. Base64 encoding increases file size by approximately 33%, so a 15 MB file becomes roughly 20 MB on the wire.

    Typical limits:
    - EDIS outbound: varies by hosting plan
    - Common recipient limits: 10–25 MB (Gmail, Outlook.com, corporate servers)

    **What to do:**
    - Use a cloud storage service and send a link rather than attaching large files directly.
    - Compress the file into a ZIP archive to reduce its size (this helps with uncompressed formats like images or CSVs, but has little effect on already-compressed files such as JPEGs or MP4s).
    - Ask the recipient whether their server has a documented attachment size limit, and confirm the exact limit with your hosting plan if needed.
  </Accordion>

  <Accordion title="Antivirus or Malware Detection">
    EDIS scans all inbound and outbound email for viruses and malware. If an attachment triggers an antivirus signature — even a false positive — the message will be blocked or the attachment will be stripped.

    **What to do:**
    - Scan the file locally with up-to-date antivirus software before sending.
    - If you believe the detection is a false positive, contact [hosting@edis.at](mailto:hosting@edis.at) with the sender address, recipient address, timestamp, and the complete error or bounce message. EDIS support can check the filter logs for the specific message.
    - Do not send potentially suspicious files without confirming their origin and integrity.
  </Accordion>

  <Accordion title="Spam Filter Triggering on Attachment">
    The spam filter evaluates the entire message, including attachment names, file types, and content patterns. A message with an attachment that matches known spam or phishing patterns — for example, a password-protected ZIP with an executable inside, or an Office document with embedded macros — may receive a high spam score and be quarantined or rejected.

    **What to do:**
    - Check the quarantine folder in the [Spamfirewall portal](https://www.spamfirewall.at) for the blocked message.
    - If the message is in quarantine, release it from there.
    - If the issue recurs, review the spam score settings in the Spamfirewall portal (see [Spam Filter](/email/spam-filter)) or contact support to have the filter rules reviewed.
  </Accordion>

  <Accordion title="Recipient Server Rejection">
    The EDIS mail server may accept and forward a message that is subsequently rejected by the recipient's mail server. In this case you will usually receive a Non-Delivery Report (NDR) or bounce email. The bounce message contains the recipient server's reason for rejection.

    Common recipient-side reasons:
    - The recipient's server also blocks the file type or enforces a smaller size limit.
    - The recipient's server applies stricter content filtering policies.
    - The sender domain lacks proper SPF, DKIM, or DMARC records, causing the message to be rejected as unauthenticated.

    **What to do:**
    - Read the full bounce message — it usually contains the specific rejection reason and the name of the rejecting server.
    - If SPF or DKIM issues are indicated, check your domain's DNS records (see [SPF Record](/email/spf-record) and [DMARC Record](/email/dmarc-record)).
    - Use a cloud sharing link as an alternative to attaching the file directly.
    - If the recipient's server is at fault, the recipient's IT department is the right contact to resolve the restriction on their end.
  </Accordion>

</AccordionGroup>

## Using Cloud Storage as an Alternative

When you cannot send a file as an attachment, the most reliable alternative is to upload it to a cloud storage service and share the link:

1. Upload the file to Google Drive, Dropbox, OneDrive, or a similar service.
2. Set the sharing permissions appropriately (e.g., "anyone with the link can view" or a specific recipient's email).
3. Copy the sharing link and paste it into your email message body.
4. Inform the recipient that the file is available via the link and note any access restrictions.

This approach bypasses all attachment size limits and file type restrictions, and works reliably across all mail systems.
