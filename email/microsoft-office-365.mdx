If you want to use Microsoft 365 (Exchange Online) as the mail platform for a domain that is registered or hosted at EDIS, you need to add a specific set of DNS records to your domain's zone in the EDIS DNS portal. Microsoft 365 provides these exact values during the domain setup wizard in the Microsoft 365 admin centre — the values are unique to your Microsoft 365 tenant and cannot be copied from documentation or screenshots.

This guide walks you through the process. Complete each phase in the order listed to avoid gaps in mail delivery during the transition.

<Warning>
  **Before changing your MX record**, make sure all required Microsoft 365 mailboxes are set up and ready to receive mail. Updating the MX record immediately routes all incoming email to Microsoft 365 — any messages sent after that point will go to Microsoft, not to your EDIS mailboxes. Plan the migration of existing messages separately; an MX change does not move stored email.
</Warning>

## Phase 1: Add and Verify Your Domain in Microsoft 365

<Steps>

### Open the Microsoft 365 admin centre

Go to [https://admin.microsoft.com](https://admin.microsoft.com) and sign in with a Global Administrator account for your Microsoft 365 tenant.

### Add your domain

Navigate to **Settings** → **Domains** → **Add domain**. Enter the domain name you want to connect (e.g., `yourdomain.at`) and click **Use this domain**.

### Complete domain ownership verification

Microsoft 365 will prompt you to prove that you own the domain. It provides a **TXT record** with a value in the format `MS=msXXXXXXXX`. 

Log in to the [EDIS DNS portal](https://pdns.edis.global/login), open the zone for your domain, and add a new TXT record:

| Field | Value |
|---|---|
| Name / Host | `@` (or your domain name, depending on the DNS editor) |
| Type | `TXT` |
| Value | The verification value shown in the Microsoft 365 wizard (e.g., `MS=ms12345678`) |
| TTL | 3600 (or as low as your zone allows) |

<Note>
  Use the exact verification value shown in **your** Microsoft 365 admin centre. The value `MS=msXXXXXXXX` is a placeholder — your actual value is different and unique to your tenant. Never copy example values from documentation.
</Note>

### Return to Microsoft 365 and click Verify

Once you have added the TXT record, click **Verify** in the Microsoft 365 admin centre. DNS propagation usually takes a few minutes; if verification fails, wait 5–10 minutes and try again.

</Steps>

## Phase 2: Add the Required DNS Records

After verification, the Microsoft 365 setup wizard lists all the DNS records you need to add. Add them all to your domain's zone in the [EDIS DNS portal](https://pdns.edis.global/login).

<Steps>

### Add the MX record

The MX record routes incoming email to Microsoft Exchange Online:

| Field | Value |
|---|---|
| Name / Host | `@` (root of the domain) |
| Type | `MX` |
| Priority | `0` (as specified by Microsoft) |
| Value | `<tenant>.mail.protection.outlook.com` (exact value from the wizard) |
| TTL | 3600 |

<Warning>
  Remove any existing MX records pointing to `mx.edis.at` before or at the same time as adding the Microsoft 365 MX record. Having both active simultaneously will cause mail to be delivered inconsistently — some messages will go to EDIS, others to Microsoft 365. Coordinate the cutover carefully.
</Warning>

### Add the SPF TXT record

The SPF record authorises Microsoft 365 servers to send email on behalf of your domain:

| Field | Value |
|---|---|
| Name / Host | `@` |
| Type | `TXT` |
| Value | `v=spf1 include:spf.protection.outlook.com -all` |
| TTL | 3600 |

<Warning>
  If you already have an SPF record for this domain (e.g., one that includes EDIS mail servers), **do not create a second TXT record**. A domain must have exactly one SPF record. Merge the `include:spf.protection.outlook.com` mechanism into your existing SPF record instead:
  ```
  v=spf1 include:spf.protection.outlook.com ~all
  ```
  Once you remove EDIS as a mail host, you can remove the EDIS SPF include as well.
</Warning>

### Add the Autodiscover CNAME record

The Autodiscover record allows Outlook and mobile clients to configure themselves automatically:

| Field | Value |
|---|---|
| Name / Host | `autodiscover` |
| Type | `CNAME` |
| Value | `autodiscover.outlook.com` |
| TTL | 3600 |

### Add the DKIM CNAME records

Microsoft 365 uses two CNAME records to point to its DKIM key infrastructure. The wizard shows both; they follow this pattern:

| Name / Host | Type | Value |
|---|---|---|
| `selector1._domainkey` | `CNAME` | `selector1-yourdomain-at._domainkey.yourtenant.onmicrosoft.com` |
| `selector2._domainkey` | `CNAME` | `selector2-yourdomain-at._domainkey.yourtenant.onmicrosoft.com` |

Copy the exact values shown in the Microsoft 365 admin centre — they are unique to your tenant and domain.

### Add any additional records (SRV, etc.)

Depending on the Microsoft 365 services you use (Teams, Skype for Business), the wizard may list additional SRV or CNAME records. Add only the records shown for the services you have actually enabled in your tenant.

</Steps>

## Phase 3: Update the EDIS Transport Entry

When email for your domain is fully handled by Microsoft 365, EDIS should no longer accept mail for that domain. Remove the transport entry in EDIS to prevent mail delivery conflicts:

1. Log in to the [EDIS customer portal](https://manage.edis.at/client/) → **Domain** → **Mail Transport**, or open the [vHost panel](https://manage.edis.at/vhost/) → **Email Addresses** → **Transport**.
2. Find the domain and remove or deactivate the transport entry.

See [Transport Entries](/email/transport-entry) for full details on this setting.

## Phase 4: Verify and Test

<Steps>

### Let Microsoft verify DNS

Return to the Microsoft 365 admin centre. Under **Settings** → **Domains**, click your domain. Microsoft will run a DNS check and indicate which records are configured correctly.

### Test email sending and receiving

Send a test email **to** your domain from an external address (e.g., a Gmail account). Confirm it arrives in the Microsoft 365 mailbox. Then send a message **from** the Microsoft 365 mailbox and confirm it is received and passes SPF and DKIM checks.

### Verify Autodiscover

Configure Outlook on a desktop or mobile device using only your email address and password. If Autodiscover is working correctly, Outlook will configure itself automatically without requiring manual server entries.

### Check your website is unaffected

Changing MX, TXT, and CNAME records does not affect your website unless you accidentally modified A or CNAME records that point to your web hosting. Verify that your website loads correctly after the DNS changes.

</Steps>
