To connect any email client — whether Outlook, Thunderbird, Apple Mail, or a mobile app — to your EDIS mailbox, you need the correct incoming and outgoing server settings. All EDIS mail connections are encrypted. Use the values in this guide exactly as shown; incorrect settings are the most common cause of login failures and missing messages.

## Incoming mail settings

### IMAP (recommended)

IMAP keeps your messages on the EDIS server and synchronises folders across all your devices. It is the recommended protocol for most users.

| Setting | Value |
|---|---|
| Incoming mail server | `mx.edis.at` |
| Port | `993` |
| Encryption | `SSL` / `SSL/TLS` |
| Username | Your full email address (e.g. `you@example.com`) |
| Password | Your mailbox password |

### POP3

POP3 downloads messages to your device. By default, most clients delete messages from the server after downloading them.

| Setting | Value |
|---|---|
| Incoming mail server | `mx.edis.at` |
| Port | `995` |
| Encryption | `SSL` / `SSL/TLS` |
| Username | Your full email address |
| Password | Your mailbox password |

<Note>
  The legacy hostname **mail.edis.at** still works for existing configurations but the current preferred hostname is **mx.edis.at**. Use `mx.edis.at` for all new setups.
</Note>

## Outgoing mail settings (SMTP)

| Setting | Value |
|---|---|
| Outgoing mail server | `mailrelay.edis.at` |
| Port | `587` (STARTTLS) or `465` (SSL) |
| Encryption | `STARTTLS` on port 587, `SSL/TLS` on port 465 |
| Authentication required | Yes |
| Username | Your full email address |
| Password | Your mailbox password |

<Tip>
  If your email client does not offer "STARTTLS" as a label, look for **TLS** or **Opportunistic TLS** for port 587. For port 465, choose **SSL** or **SSL/TLS**.
</Tip>

## Encryption label reference

Some email clients use slightly different labels for SSL. Use this reference if you cannot find a matching option:

| If the guide says | Try selecting in your client |
|---|---|
| `SSL` | `SSL/TLS` |
| `STARTTLS` | `TLS`, `Opportunistic TLS` |

## IMAP folder path (advanced)

In most cases you do not need to change the IMAP path prefix. If your email client shows missing or incorrectly mapped folders (Sent, Drafts, Trash), try setting the **IMAP root folder path** or **IMAP path prefix** to `INBOX` for the affected account.

After making this change, verify that:
- Incoming messages appear in the Inbox.
- Sent messages are saved in the Sent folder.
- Drafts and deleted items are stored in the correct folders.

<Warning>
  Do not change the IMAP path prefix globally for all accounts. Apply it only to the EDIS account where folders are missing or misaligned.
</Warning>

## Sending from a website or application

If you are sending email programmatically — for example from a PHP application or a CMS plugin — use the same SMTP settings as above. Note that port availability may differ between a desktop computer and a shared hosting environment. If you encounter a connection error from your web application, include the following information when contacting support:

- The affected website or mailbox address
- Whether the issue is with sending (SMTP) or receiving (IMAP)
- The SMTP hostname, port, and TLS setting you are using
- The exact error message (with any passwords removed)
- The date and time of the failure, including time zone

Do not send passwords in a support ticket. Webmail access uses a separate path and a successful webmail login does not confirm that SMTP from your application is correctly configured.
