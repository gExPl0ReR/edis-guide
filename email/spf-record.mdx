An SPF (Sender Policy Framework) record is a DNS TXT entry that tells receiving mail servers which IP addresses are authorised to send email on behalf of your domain. Without a correct SPF record, messages from your domain may be marked as spam or rejected outright by recipient servers such as Gmail or Microsoft.

EDIS automatically sets an SPF record for newly registered domains. If your domain was created before this became the default, or if you manage DNS manually, follow this guide to add or update your SPF record.

## The standard EDIS SPF record

For domains that send mail exclusively through EDIS infrastructure (webhosting and the `mailrelay.edis.at` relay), use the following record:

```dns
@ TXT "v=spf1 a:spf.edis.at -all"
```

**Explanation of each part:**

| Component | Meaning |
|---|---|
| `@` | Represents the domain itself (place this in the leftmost "Name" or "Host" column in your DNS editor) |
| `v=spf1` | Identifies this as an SPF version 1 record |
| `a:spf.edis.at` | Authorises all IP addresses listed in the `spf.edis.at` DNS record |
| `-all` | Hard fail — any server not listed above is not authorised to send for this domain |

<Warning>
  Every domain must have **at most one** SPF TXT record for the same hostname. If your domain already has an SPF record (a TXT record starting with `v=spf1`), do **not** create a second one. Instead, edit the existing record to include the EDIS mechanism. Two SPF records on the same name cause a permanent error and will break email delivery.
</Warning>

## Softfail vs. hard fail

The `-all` at the end of the record is a **hard fail** (`-all`). You can use `~all` (tilde) for a **softfail** instead:

```dns
@ TXT "v=spf1 a:spf.edis.at ~all"
```

| Suffix | Meaning | When to use |
|---|---|---|
| `-all` | Hard fail — unauthorised senders should be rejected | When you are confident all sending services are listed |
| `~all` | Softfail — unauthorised senders are flagged but not necessarily rejected | During initial setup or when testing |

<Note>
  A stricter rule (`-all`) only makes sense when you have accurately listed **all** legitimate sending services. If you also send through Google Workspace, a newsletter tool, or any other platform, you must include their authorisation mechanisms in the same SPF record before using `-all`.
</Note>

## Adding other sending services

If you send email through services in addition to EDIS — for example a newsletter platform or Microsoft 365 — extend your EDIS SPF record to include them rather than creating a new record:

```dns
@ TXT "v=spf1 a:spf.edis.at include:_spf.google.com -all"
```

Consult your other sending service's documentation for their required SPF mechanism, then add it alongside `a:spf.edis.at`.

## EDIS mail server IP addresses

The `a:spf.edis.at` reference automatically resolves to the current list of EDIS outgoing mail server IP addresses. Using this reference is strongly recommended over listing individual IPs, as EDIS may update its infrastructure over time. For the current list of IPs covered by this record, see [EDIS Mail Server IP Addresses](/email/ip-addresses-spf) or look up `spf.edis.at` at [MX Toolbox](https://mxtoolbox.com/SuperTool.aspx?action=a%3aspf.edis.at&run=toolpage).

## Where to add the SPF record

Add the SPF TXT record in the authoritative DNS zone for your domain. If your domain uses EDIS nameservers (`ns1.edis.global` / `ns2.edis.global`), manage DNS at the [EDIS DNS portal](https://pdns.edis.global/login). If DNS is managed elsewhere, log in to that provider's DNS panel and add a TXT record with:

- **Name/Host:** `@` (or leave blank, depending on the provider's interface)
- **Type:** `TXT`
- **Value:** `v=spf1 a:spf.edis.at -all`

DNS changes typically propagate within minutes to a few hours.
