When email is sent through EDIS infrastructure — whether from a hosted mailbox, a web application, or the authenticated SMTP relay — it originates from one of a number of outgoing mail servers. Depending on the type and origin of the sending, different servers and IP addresses may be involved in delivering the message to external recipients.

Understanding which IP addresses EDIS uses for outbound email is useful if you are:

- Setting up SPF records manually (without using the `a:spf.edis.at` include shorthand)
- Configuring firewall or IP allowlists at your email recipient's side
- Investigating a delivery failure related to IP reputation

## The recommended approach: use `spf.edis.at`

Rather than listing individual EDIS IP addresses in your SPF record, use the maintained `a:spf.edis.at` reference. EDIS keeps this DNS entry up to date as infrastructure changes. Your SPF record then stays correct automatically without any manual updates.

```dns
@ TXT "v=spf1 a:spf.edis.at -all"
```

This single record authorises all current EDIS outgoing mail server addresses. See [Set Up an SPF Record](/email/spf-record) for the full setup guide.

## Looking up current EDIS mail server IPs

The live list of IP addresses covered by `spf.edis.at` is published in DNS. You can look it up at any time using a tool like [MX Toolbox](https://mxtoolbox.com/SuperTool.aspx?action=a%3aspf.edis.at&run=toolpage):

```
a:spf.edis.at
```

This query returns all IPv4 and IPv6 addresses currently registered for EDIS outgoing email. Because infrastructure evolves, always use this live lookup rather than copying addresses from a static list.

<Note>
  EDIS recommends using `a:spf.edis.at` in your SPF record rather than hard-coding individual IP addresses. If an IP address changes or a new server is added, the `spf.edis.at` reference updates automatically — a static IP list in your SPF record would become outdated and could cause delivery failures.
</Note>

## SPF configuration for domains using EDIS

EDIS automatically configures SPF records for domains created through its platform. If you are setting up a domain that was registered elsewhere or migrated to EDIS, verify whether an SPF record already exists. You should have **exactly one** TXT record starting with `v=spf1` per domain name.

To check for an existing SPF record, query your domain's DNS:

```bash
# Using dig
dig TXT yourdomain.com

# Using nslookup
nslookup -type=TXT yourdomain.com
```

Look for a line containing `v=spf1`. If one exists, edit it to include the EDIS mechanism rather than adding a new one.

<Warning>
  Having two TXT records that both start with `v=spf1` on the same hostname is a permanent SPF error (permerror). Receiving servers will treat this as an authentication failure, which can cause legitimate email to be rejected or flagged as spam.
</Warning>

## Mail server infrastructure

EDIS operates multiple servers involved in sending email on behalf of hosted domains and authenticated SMTP relay users. These include:

- **Webhosting outgoing mail** — mail generated by PHP applications and CMS installations on shared hosting
- **Authenticated SMTP relay** (`mailrelay.edis.at`) — mail sent by email clients using SMTP authentication
- **Transactional and routing infrastructure** — servers involved in routing and relaying

All of these are covered by the `a:spf.edis.at` reference. You do not need to enumerate them individually in your SPF record.

## Firewall and allowlist use

If you need to allow inbound connections from EDIS mail servers at a recipient firewall, look up the current addresses from `spf.edis.at` and use those. For persistent allowlist rules, set a reminder to re-check the list periodically in case of infrastructure changes. Contact [hosting@edis.at](mailto:hosting@edis.at) if you need confirmation of specific IP ranges for a security configuration.
