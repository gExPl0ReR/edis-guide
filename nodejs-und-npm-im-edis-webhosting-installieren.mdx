Sie benötigen ein [Ristretto-Hosting](https://www.edis.at/de/hosting/produkte/ristretto) oder höher mit passendem **SSH-Zugang**. Prüfen Sie die Voraussetzungen Ihres konkreten Webhosts.

<Note>
Die Installation von Node.js und npm ist keine Zusage für einen dauerhaft laufenden Node.js-Webserver. Klären Sie Prozessverwaltung, Ports und gegebenenfalls einen Reverse Proxy vorab, wenn Sie mehr als Build-Werkzeuge benötigen.
</Note>

## Installation vorbereiten

Verbinden Sie sich via SSH auf Ihren Webhost:

```bash
ssh ssh.at.edis.global -l VHOSTKEY -p 22
```

Wechseln Sie zB: ins Verzeichnis www/

```bash
cd www/
```

und legen ein neues Verzeichnis an, zB: nodejs

```bash
mkdir nodejs
```

## Passende Version herunterladen

Wechseln Sie nach dem Anlegen mit `cd nodejs` in das neue Verzeichnis, bevor Sie Dateien herunterladen. Wählen Sie unter [Node.js: Offizielle Downloads](https://nodejs.org/en/download) eine unterstützte Version für die bestätigte Serverarchitektur und prüfen Sie die veröffentlichten Prüfsummen. Ersetzen Sie vxx.x.x und den Dateinamen in den folgenden Befehlen durch die tatsächlich gewählte Veröffentlichung.

```bash
wget https://nodejs.org/dist/vxx.x.x/node-vxx.x.x-linux-x64.tar.gz
tar -xzf node-vxx.x.x-linux-x64.tar.gz
```

## Suchpfad und Version prüfen

Wechseln Sie ins Verzeichnis der Installation:

```bash
cd node-vxx.x.x-linux-x64/bin
```

Prüfen Sie den kompletten Pfad mit pwd:

```bash
pwd
```

Wenn Sie im bin-Verzeichnis der gewählten Installation stehen, können Sie den Suchpfad für die aktuelle Sitzung so erweitern: `export PATH="$(pwd):$PATH"`. Prüfen Sie anschließend mit `command -v node` und `command -v npm`, welche Programme aufgerufen werden. Eine dauerhafte Anpassung Ihrer Shell-Konfiguration muss gesondert eingerichtet werden.

Prüfen Sie die Version mit:

```bash
node -v
```

Historische Beispielausgabe: `v20.9.0`. Maßgeblich ist Ihre gewählte, unterstützte Version.

```bash
npm -v
```

Historische Beispielausgabe: `10.1.0`.

## Build-Werkzeug oder dauerhaft laufende Anwendung?

Ein Build-Werkzeug erzeugt Dateien und beendet sich anschließend. Ein dauerhaft laufender Node.js-Webserver benötigt zusätzlich Prozessverwaltung, erreichbare Ports und gegebenenfalls einen Reverse Proxy. Die Installation von Node.js und npm im eigenen Account ist daher kein Nachweis für verwaltetes Node.js-Hosting oder eine zugesicherte dauerhafte Prozessverfügbarkeit.

<a id="-w-js" />

## Version, Zugang und Ressourcen prüfen

Verwenden Sie die SSH-Zugangsdaten des betroffenen Webhosts und prüfen Sie, ob Ihr gebuchter Tarif SSH unterstützt. Wählen Sie eine unterstützte Node.js-Version, die zur Anwendung und zur Hosting-Umgebung passt. Versionsnummern, Architektur und Dateinamen im Beispiel müssen vor der Ausführung angepasst werden; die gezeigten Versionsausgaben sind keine aktuelle Empfehlung.

Kontrollieren Sie nach der Installation, welche Programme und Versionen tatsächlich aufgerufen werden. Berücksichtigen Sie dabei den Suchpfad sowie den Speicher- und Ressourcenverbrauch Ihres Hostingpakets.

<a id="yTNeC" />

## Dauerhaften Betrieb vorab klären

Wenn Ihre Anwendung Docker, PM2, eigene Serverports oder einen Reverse Proxy voraussetzt, klären Sie diese Anforderungen vorab mit dem Support. Aus der Möglichkeit, eigene Werkzeuge zu installieren, ergibt sich keine Zusage für diese Betriebsarten oder für Anwendungssupport. Beschreiben Sie, ob Sie nur Builds ausführen oder einen dauerhaft erreichbaren Dienst betreiben möchten.
